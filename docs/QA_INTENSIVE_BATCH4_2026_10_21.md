## Confirmed failures and repairs

- Identical POST retries created redundant estimate revisions (baseline reproduction:1 revision for the same payload). New saves have account-scoped transactional idempotency receipts. Lost-response retries return the original receipt, including after a newer edit, without overwriting that newer edit. Reusing an operation identifier for different details returns409. Identical legacy requests also no-op. Owner locks ensure only one active property record and one usage charge.
- A stale pricing save reset a newer Booked status to Estimate (baseline reproduced). Booking/date/payment fields now belong to their dedicated update endpoints and are preserved during pricing edits. Each endpoint takes the same owner lock before its read/modify/write, preventing concurrent fields from overwriting one another. New browser editors use server version hashes and If-Match; conflicting saves return409 with retained local measurements. Legacy API callers without If-Match retain compatibility; simultaneous independent legacy pricing edits still have last-write behavior with revisions.
- A failed/invalid property request reserved and committed usage before geocoding/provider results. Reservations now commit with successful lookup responses and otherwise roll back. Lookup retries use account-scoped receipts; simultaneous repeats run the provider once and charge once. The owner lock is held during this provider request, so other writes for that business can wait for the provider timeout. Different businesses have independent owner locks.
- Both loadProperty and the address input handlers cleared the workspace before the replacement property was accepted. Address edits now retain the old geometry/customer/loaded address while pricing validation blocks mismatched address/measurement quotes; a successful new-property load clears the old customer once. Request/auth/address failures now leave prior measurements, rates, property address and imagery intact. Repeated clicks share one in-flight request. Drafts and changed work warn before refresh/navigation; they are not automatically persisted across a deliberately confirmed discard or browser crash.
- Estimate save requests had no bounded timeout or cross-request retry identity. New single-flight saving freezes the exact request and its operation identifier, aborts unresponsive save requests at30seconds, retains retry state and displays specific expired-login/conflict instructions. A401 prevents opening the customer report. JSON property requests now return JSON401 instead of redirecting into a login HTML parse error.
- Concurrent employee creation could race between duplicate checks and insertion. Employee creation serializes its identity checks; repeated creation returns an existing-email message without duplicate employees/500. Disabling an employee now revokes existing sessions once; repeated disable is idempotent, and reactivation does not revive an older session. Signup versus employee-creation identity races are not claimed resolved by this employee-only identity lock.
- PostgreSQL REAL stores float32, risking customer-visible cents on large totals. New schema initialization widens estimate/revision total_price and total_area to DOUBLE PRECISION. It does not rewrite historical payloads or repair previously rounded column values. Actual PostgreSQL precision/concurrency checks run in a disposable CI service; see final run outcomes.
